# Границы симуляции: проект

Библиотека `Libs/Boundaries` — обычный C++ без runtime Lattice, без предметной области
(атомы, элементы) и без рендера. На входе — колонки позиций и скоростей (SoA), время и
описание геометрии; на выходе — вклад в силы и исправленные позиции/скорости.

## Границы модулей

| Где | Что | Зависит от |
|---|---|---|
| `Libs/Boundaries/Boundaries` — цель `Boundaries` | модель: `Space`, `Shape`/`Program`, материалы, законы (параметры и смысл), `ParticleLayout`, проверки конфигурации | `glm`; без runtime Lattice, без бэкендов, без предметной области |
| `Libs/Boundaries/cpu` — `Boundaries.cpu` | стековая машина, `Walls`, аниматор на CPU по `StdData::SoA` | `Boundaries`, `StdData` |
| `Libs/Boundaries/wgpu` — `Boundaries.wgpu` | WGSL-стековая машина и законы, compute-проход по `GpuSoA` | `Boundaries`, `Libs/Wgpu` |
| `Libs/Boundaries/cuda` — `Boundaries.cuda` | позже | `Boundaries`, `Libs/Cuda` |
| `Packages/ClassicMD` (`compose.cpp`) | узлы `Space`/`Geometry`/`Walls`/аниматора в ветке симуляции, параметры под `executeOn(commands)`, выбор бэкенда | бэкенд-цель |
| `Packages/Graphics` | объект сцены отрисовки геометрии (трассировка лучей по SDF) | `Boundaries.wgpu` (общая WGSL-машина) |

* Ядро Lattice не меняется.
* Симуляция не знает о рендере: геометрию рендер получает так же, как частицы — через
  опубликованный контракт и копию командой очереди симуляции.
* WGSL-код геометрии один: его подключают и compute-проход границ, и отрисовка.
* Ядра пишутся «на раздел» (`AGENTS.md`): границы локальны по частице, `Space` и
  `Geometry` — общие данные только для чтения.

## Три слоя

| Слой | Что задаёт | Кто читает |
|---|---|---|
| `Space` | Прямоугольная коробка-система координат и периодичность по осям: минимальный образ, заворот, сетка соседей | интегратор, поиск соседей, силовые поля, `Walls` |
| `Geometry` | Тело допустимой области: функция расстояния `d(p, t)` (`d > 0` — внутри, `d < 0` — в стенке), нормаль `∇d`, материал ближайшей поверхности | `Walls` |
| `Walls` | Закон отклика поверхности по `(d, n, v_s, материал)`: жёсткое отражение, мягкая сила, … | шаг симуляции |

`Space` всегда коробка: хеширование и сетка соседей строятся по ней и не зависят от формы
тела. Форма — только в `Geometry`.

## Geometry: SDF-программа

Дерево примитивов и операций компилируется в плоскую постфиксную программу (байткод:
код операции + параметры) в одном буфере. CPU и GPU исполняют один и тот же буфер на
стековой машине; результат вычисления — `{d, материал, движение}`.

* Примитивы: коробка, сфера, капсула, цилиндр, полупространство; бесконечные варианты
  вдоль оси (для периодичности).
* Операции: объединение, пересечение, вычитание, сглаженное объединение, скругление
  (`d − r`), оболочка (`|d| − t`), перенос/поворот/масштаб.
* Новый примитив или операция — новый код операции: C++-функция + WGSL-функция + строка
  таблицы. Остальное не меняется.
* Программа и параметры — данные: замена формы — команда очереди симуляции, без
  пересборки ветки и перекомпиляции шейдера.

Ограничения: сглаженные операции и неравномерный масштаб дают оценку расстояния, а не
точное расстояние — жёсткая проекция делается итерациями `p −= d·n` (2–3). Острые
вогнутые углы по умолчанию скругляются. Толщина стенки должна превышать `|v|·dt`
(проверка конфигурации).

## Анимация

Параметры программы — функция времени: аниматор (отдельный объект, правило «время →
параметры», например движение по траектории или вращение) на каждом шаге пишет новый
буфер параметров. Предыдущий буфер сохраняется.

* Нормальная скорость поверхности — общий способ для любой анимации:
  `v_n(p) = (d_prev(p) − d(p)) / dt` (два вычисления программы).
* Касательная скорость (мешалка, трение) — из жёсткого движения узла преобразования:
  `v = v_lin + ω × (p − c)`; программа возвращает номер движения ближайшей поверхности.
* Отклик стенки считается в системе поверхности: отражается относительная нормальная
  скорость, мягкая сила зависит от `d` в текущий момент.
* Разметка ячеек сетки («глубоко внутри» / «у поверхности» / «снаружи») делается с запасом
  на максимальное смещение поверхности до следующей перестройки сетки соседей.

## Материалы

Программа возвращает номер материала ближайшей поверхности; таблица материалов хранит
закон отклика и его параметры. Сейчас — один материал по умолчанию на всё тело, номер уже
есть в результате и в буфере, полная таблица — позже.

## Walls: законы отклика

Закон — одна структура: имя, параметры (POD фиксированного размера), CPU-функция,
WGSL-фрагмент, нужные стадии (`Constrain` — после сдвига позиций, `Force` — при расчёте
сил). Список законов — compile-time список; выбор — поле материала (данные).

* `Hard` — вытолкнуть на поверхность, отразить относительную нормальную скорость
  (стадия `Constrain`).
* `Soft` — `F = −U′(d)·n` с отсечкой (степенной, как в старом `WallForceField`, и
  гармонический; стадия `Force`).
* Задел (проверка расширяемости модели, без реализации): открытая, поглощающая (отложенное
  удаление), термостенка (генератор случайных чисел на частицу), трение (касательная
  скорость).

## Производительность

* Частицы обходятся по колонкам SoA; подвижные идут первыми, неподвижные пропускаются.
* SDF вычисляется только для частиц в ячейках «у поверхности»; ячейки «глубоко внутри»
  пропускаются, «снаружи» пусты.
* Выбор закона — по материалу ближайшей поверхности; ветвление одинаково для частиц у
  одной поверхности.
* Для сложных тел программу можно запечь в 3D-сетку расстояний (на GPU — текстура);
  интерфейс не меняется.

## Периодичность и геометрия

Геометрия вычисляется в координатах `Space` после заворота. Вдоль периодической оси тело
согласовано на шве (удобно — бесконечными примитивами). При сборке SDF сравнивается на
противоположных гранях коробки по сетке точек: разрыв — ошибка конфигурации.

## Встраивание

* Шаг (Verlet): сдвиг позиций → `Walls::constrain` + заворот `Space` → силы (поля с
  минимальным образом `Space`) + `Walls` стадии `Force` → коррекция скоростей.
* В ClassicMD `Space`, `Geometry`, `Walls`, аниматор — узлы ветки симуляции, параметры —
  обычные `param` под `executeOn(commands)`; `Space` передаётся интегратору, сетке соседей
  и силовым полям аргументом конструктора.
* GPU: compute-проход на шаг (программа и параметры — storage/uniform, колонки — из
  GPU-таблицы по смещениям). Нужен compute pipeline в WGPU.

## Отрисовка геометрии

Не часть библиотеки границ. Объект сцены Graphics трассирует лучи по той же SDF-программе
(общая WGSL-машина из `BoundariesGpu`), пишет `frag_depth` — частицы и стенки корректно
перекрываются. Сначала непрозрачная поверхность, затем полупрозрачная (прозрачный проход
после непрозрачного), чтобы видеть частицы внутри. Программа и параметры попадают в рендер
копией командой очереди симуляции, как частицы.
