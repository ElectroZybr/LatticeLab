Рамки: вьюпорт общий, содержимое — `SceneObject`; данные для рендера — GPU-таблица
(линейная копия SoA одним `writeBuffer` для CPU-симуляции, сам буфер — для GPU-симуляции);
рендер про модель не знает; сцена собирается кодом, сохраняется через `Serializer`.

- [x] `WGPU::GpuSoA : Lattice::Table` — GPU-зеркало `StdData::SoA` (та же раскладка, загрузка одним `writeBuffer`) и GPU-владеемая таблица (`addColumn`/`resize`); `ColumnView` без данных на хосте не разыменовывается

### Сравнение исполнителей в бенчах

Проект и полный чеклист — `../Lattice/Docs/ru/BmRunner.md`: работа через канал к
исполнителю раскладывается на фазы (`Prepare`, `Transfer`, `Issue`, `Execute`, `Complete`,
`Unaccounted`); длительности исполнителя приходят отдельно от часов хоста; режимы
`Resident` / `Offload`, ось `Batch`, подгонка `a + b·N` и порог `N*` для пары исполнителей.
GPU — первый потребитель, тот же словарь подходит сетевым протоколам и пулу потоков. На CPU
канал — иерархия памяти: перенос по уровням оценивается по счётчикам кешей и калибровке,
`Resident` / `Offload` — горячий / холодный кеш.

- [x] BmRunner (`../Lattice`): `Phase`, `Trace`, capability `Phases`, подгонка `fixed + per·N` по фазам, пары исполнителей и `N*`, холодный кеш, вывод, тесты на синтетическом исполнителе
- [ ] BmRunner: ось `Batch`, калибровка уровней памяти и оценка переноса по счётчикам, объявленный объём работы
- [x] `Wgpu::Timer` (timestamp queries); в `Trace` — через `deferIntervals` (договорённость по форме интервала, без адаптера)
- [x] `Wgpu.bench`, `Boundaries.bench`: фазы, пары CPU/GPU, `Resident` / `Offload`
- [ ] Wgpu: загрузка через `copyBuffer` с timestamps (сейчас `writeBuffer` меряет только staging), постоянный staging для readback (сейчас 1,6 мс на вызов), разобрать `Complete` ≈ 2 × `Execute@dev`
- [ ] `GpuWalls`: больше 65535 групп на измерение (≈ 4,2 млн частиц при группе 64) — двумерный dispatch
