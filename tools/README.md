# Генерация регистрации плагинов

`Lattice::Component` — пустой невиртуальный маркер. Наследуйте его публично
на корневом интерфейсе или самостоятельном компоненте. Потомки участвуют
автоматически; повторять список классов или баз не нужно. `configure(Node&)`
остаётся необязательным методом конкретного типа.

```cpp
#include <Lattice/Kernel/Component.hpp>
namespace Example {
struct API : Lattice::Component { virtual void run() = 0; };
struct Engine : API { void run() override {} };
struct Description { int count; }; // не регистрируется
}
```

Для плагина подключите `add_rules("lattice.plugin_codegen")` в его xmake target.
Удалите ручную функцию `plugin_register`; `plugin_shutdown` и другие
пользовательские функции остаются в `PluginInit.cpp`. Примеры: GPU и WGPU.
Требуются Python 3, Clang, libclang и совместимые Python bindings `clang.cindex`.
На Arch Linux это пакеты `clang` и `python-clang` (Python также должен быть установлен).

Правило перед сборкой анализирует `.h`/`.hpp` внутри каталога плагина
с флагами его xmake target. Clang проверяет тела методов, поэтому заголовки
должны собираться с этими флагами. `.cpp`-локальные классы не сканируются.
Сгенерированный файл лежит в `build/.gens/<target>/.../plugin_register.cpp`;
он переписывается только при изменении результата. Внешние типы используются
для определения наследования, но не регистрируются повторно. Их плагины должны
быть загружены раньше, как и при ручной регистрации.

Генерируются две независимые точки входа:

- `plugin_register(Node&)` — совместимость с действующим Runtime. Создание,
  configure и уничтожение по-прежнему реализует `Node::blueprint<T>()`.
  Ограничения старого дерева сохраняются: один базовый Lattice-тип и уникальные
  короткие имена. Множественные базы вызывают ошибку генератора.
- `plugin_register_blueprints(Blueprints&)` — регистрация полного имени и графа
  непосредственных Lattice-баз. Поддерживает множественное наследование.
  Runtime пока не вызывает эту функцию; фабрики и преобразования указателей
  в новый реестр ещё не перенесены.

Отдельно получить только графовую регистрацию можно через
`python3 tools/generate_plugin.py --plugin Plugins/Example --output /tmp/register.cpp -- -std=c++20 -I.`.
Опция `--legacy` добавляет совместимую регистрацию для старого Runtime.

Маркер не появляется в реестре. Не используйте `Component*` как общий указатель:
при множественном наследовании подобъект маркера может быть неоднозначным.
Шаблоны компонентов требуют конкретных нешаблонных обёрток; закрытые базы,
закрытые вложенные компоненты и анонимные namespaces отвергаются.

Проверка генератора: `python3 -m unittest discover -s tools/tests -v`.
